# Contributing

Several people and coding agents often work in **one shared checkout at the same time**, each on its own paths. The
git rules below exist so that nobody destroys someone else's uncommitted work. They apply to humans and agents alike.

## Git rules for a shared working tree

1. **Never** run `git stash`, `git reset` (any mode), `git checkout -- <path>` / `git restore` on paths you did not
   change, `git clean`, `git checkout <branch>` / `git switch`, `git rebase`, or `git commit -a` / `git add -A` /
   `git add .` in the shared tree. Each of these can silently take or discard another workstream's changes.
2. **Stage only your own paths**, explicitly: `git add path/one path/two`, then check `git diff --cached --stat`
   before committing. If a file you need to change has someone else's uncommitted edits, do not commit it; tell its
   owner.
3. **`index.lock` exists?** Another commit is in progress. Wait a few seconds and retry; never delete the lock file.
4. **Need a clean state** (a clean-clone check, a bisect, an experiment)? Use a separate worktree, and remove it when
   done:
   ```sh
   git worktree add /tmp/queuebit-clean-$(date +%s) HEAD
   # ... work there ...
   git worktree remove /tmp/queuebit-clean-<ts>
   ```
5. Do not rewrite published history (no force-push to `main`, no amending a commit that is already pushed or that
   someone else may have built on).
6. Generated files (`devnet/deploy/addresses*.json`, `apps/extension/src/generated/`, `packages/watcher-core/src/generated/`,
   the companion registry's ABI sections, committed `wasm/`) are regenerated by their owner's script, never edited by
   hand. Commit them together with the change that caused them.
7. Never commit secrets. The only keys in the repo are the public devnet/anvil test keys listed in `devnet/README.md`.

## Commit messages

[Conventional Commits](https://www.conventionalcommits.org/): `type(scope): summary`, imperative, lower case, no final
period, about 72 characters. The body (optional) says why, and cites what it relies on (a spec line, a measurement, a
review). Examples from the history:

```
feat(companion): sign tx-type 3 role-executor requests (compatible 4337 accounts)
fix(extension): 4337 review: local CREATE2 account address, callGasLimit floor, token price bounds
test(g1): re-run on the typed-registration implementation (a-g PASS)
docs(backlog): tick the companion tx-type 3 and recovery challenge items
chore(deploy): redeploy QueueBitAccountImpl and the 7579 modules with the typed registrations
```

Types: `feat`, `fix`, `test`, `docs`, `chore`, `refactor`, `perf`, `ci`, `build`. Scopes are the component:
`account`, `modules`, `roles`, `privacy`, `pq-signer`, `groth16`, `frames`, `ur`, `rpc`, `extension`, `companion`,
`watcher`, `bench`, `devnet`, `deploy`, `g1`, `ci`, `release`, `security`, `backlog`, `plan`, `lean-sphincs`,
`leanpool-node`.

Commits made with an AI assistant end with its `Co-Authored-By:` trailer.

When a commit lands a `docs/plan/BACKLOG.md` item, tick it in the same or the next commit and cite the hash.

## Before you push

From the repository root (CI runs the same, see `.github/workflows/ci.yml`):

```sh
pnpm install --frozen-lockfile
pnpm typecheck && pnpm lint && pnpm test && pnpm build
cd contracts && forge build && forge test && forge fmt --check && ./script/lint-verify.sh
```

Plus, when you touched them: `pnpm --filter @queuebit/companion e2e`, `pnpm --filter @queuebit/extension e2e`,
`cd contracts/devnet-tests/4337 && bun run e2e`, and the devnet suites (`README.md` "Quickstart"). A change to
`packages/pq-signer/rust`, `packages/groth16/rust` or `packages/lean-sphincs/rust` must rebuild and commit `wasm/`
(`bash scripts/build-wasm.sh`):
CI rebuilds it and fails on any byte difference.

## Dependencies

- Exact versions only (`.npmrc` `save-exact=true`); `pnpm-lock.yaml` is committed and CI installs with
  `--frozen-lockfile`.
- No dependency lifecycle scripts: `pnpm-workspace.yaml` has an empty `onlyBuiltDependencies` and
  `strictDepBuilds: true`, so an install fails if a new dependency wants one. Adding to the allowlist is a reviewed
  change with a reason.
- Check the license before adding anything that ships (the extension, the companion, the WASM crates must stay
  MIT-compatible: see `docs/plan/IMPLEMENTATION-NOTES.md` on snarkjs, Kohaku and circom). Copied or adapted code goes
  in `THIRD_PARTY.md` with its origin commit and license.
- GitHub Actions are pinned by full commit SHA with the release in a comment.

## Security

Report vulnerabilities privately: [`SECURITY.md`](SECURITY.md). Do not open public issues for them.
